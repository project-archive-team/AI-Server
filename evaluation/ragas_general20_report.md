## 해석

- 생성 답변은 대부분 검색 문맥에 충실했고 질문 의도에도 잘 맞았습니다.
- 검색 Recall은 전반적으로 양호하지만, 임베딩 설정·삭제 멱등성 문항에서 기준 답변의 일부 근거가 누락됐습니다.
- 검색 Precision은 절반의 문항만 권장 기준을 충족했습니다. 관련 코드가 검색되더라도 테스트 코드, README, 인접 기능 청크가 함께 상위에 배치되는 경우가 많았습니다.
- 14번과 17번은 최신 프롬프트 규칙이 운영 벡터 저장소의 상위 검색 결과에 충분히 노출되지 않았습니다.
- 18번은 생성 API 재시도를 물었지만 임베딩 API의 429 재시도 커밋과 코드가 검색되어 질의와 근거가 어긋났습니다.

## 다음 개선 우선순위

1. 운영 벡터 저장소를 최신 `services.py`와 문서로 다시 색인합니다.
2. 함수명·API명 같은 식별자 질의에는 키워드 검색을 결합하는 하이브리드 검색을 검토합니다.
3. 동일 파일의 인접·중복 청크가 과도하게 반환되지 않도록 artifact 단위 다양화 또는 중복 제거를 적용합니다.
4. 14번·17번·18번 문항은 사람이 원문과 기준 답변을 다시 검토해 골든셋 확정 여부를 결정합니다.

이 결과는 이전 40문항 평가와 데이터셋 및 평가 범위가 다르므로 모델 성능의 직접적인 전후 비교가 아니라 평가 설계 개선에 따른 방향성 비교로 사용해야 합니다.
